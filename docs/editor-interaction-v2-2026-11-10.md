# RMD 可视化编辑器交互 V2 · 验收记录（2026-11-10）

## 分支与约束

- 隔离工作树：`E:/Recalloom-editor-interactions`，分支 `feat/editor-interaction-v2`，基线 `main@9e75a6e`。
- 目标是解决用户逐项指出的八类交互缺陷。开发不直接修改生产数据库，也不在验收前覆盖 main。
- Markdown/RMD 始终是权威内容；可视化操作只修改本地草稿，页面显式保存时才提交 D1。

## 已实现

1. **真正右侧 Drawer**：桌面端 `BlockEditorPanel` 通过 Portal 挂载在 `document.body`，使用固定定位和右侧进入动画，不再是文档网格的第二列，不改变文章容器的宽度；移动端为从下方进入的全屏 Drawer，顶部固定预览。对于很窄的桌面视口，独立 Drawer 可能覆盖文章右侧，这仍需要结合用户的最终体验偏好确定是覆盖还是重排整个页面，而不能退回内嵌双列。
2. **所见即所得**：Callout / Details / Tabs / Chat 等结构标题、LinkCard 标题、Figure 图注、Table 图注都在原文字节点 `contentEditable`，不再点击后替换成 `TextInput`。支持 Enter、Escape、失焦；点击标题不会触发 Details 折叠。表格图注完全位于 ProseMirror `contentDOM` 之外，更新通过单笔表格属性事务提交。
3. **小尺寸浮动文字工具栏**：10 个约 30×30px 的纯图标按钮，统一 Tabler 和公共图标尺寸 token，不出现文字标签；上标和下标等非高频语法保留在更多功能中。修复工具栏/下拉菜单夺焦时的选区丢失，保留有效的文档版本校验。
4. **桌面右键菜单**：Astryx ContextMenu 明确限制约 244px 宽，操作划分为剪贴板、文字格式、块操作和历史分组；菜单行有 16px 左侧图标。触屏设备保留系统原生文字选区与长按菜单。
5. **外部结构块把手**：只有 `richContainer`、`richLinkCard` 和 `wikiEmbed` 等明确的 RMD `:::` 块显示把手，普通段落、标题、列表、代码等不出现独立块把手。把手通过 Portal 放在块的右外侧，空间不足时放左外侧或上方，不遮挡内容。支持键盘菜单和移动端可达定位。
6. **拖动时的物理让位**：原块位置保留半透明占位，鼠标跟随浮动缩略卡，目标位置有预留槽；相邻块在拖动中按真实块高度进行平滑位移，放手后才通过 ProseMirror 一次性事务改变顺序，支持单次撤销。为了不触碰 ProseMirror 管理的段落 DOM，位移使用临时独立样式表；拖动结束后彻底清理。
7. **选中块描边**：hover、右键菜单及开始拖动时对明确的结构块渲染外轮廓；单击普通正文时清除结构块选中。
8. **拖动指针视觉**：禁用浏览器默认遮挡内容的半透明拖拽截图，用跟随指针的浮动预览卡展示块标题与摘要，拖动时使用 grabbing 光标。

## 自动化验收

- `pnpm check`：通过。包含 RMD 语法入口审计、图标规范、帮助同步和两套 TypeScript 检查。
- `pnpm test`：**285 / 285** 单元测试通过（35 suites）。
- `pnpm build:web`：通过。构建仍有较大 Chunk 的既有警告，后续性能专项处理。
- `pnpm test:editor`：在五个隔离的 Wrangler / D1 服务（8799、8815、8825、8826、8827）**24 / 24 个浏览器脚本一次完整串行通过**。
- 单项重点：桌面 1280px 和移动 390px / 320px；真实固定 Drawer 和正文宽度不变；块外把手与段落无把手；约 234px 右键菜单、带图标分组；10 个无文字、尺寸一致的浮动按钮；Callout / LinkCard / Figure / Table 原有 DOM 节点编辑与 Escape；拖动过程中相邻段落实际位移 **125px**；同父容器嵌套拖动、跨父拒绝、Ctrl+Z、临时样式清理；草稿不提前写入 D1。

## 待实机验收和后续

- 浏览器测试基于 Windows Edge Headless，**并不等于真实 iOS Safari / Android 触控拖动、原生选字与软键盘行为已经验收**。
- 桌面固定 Drawer 独立于正文布局，但在宽度不足时可能覆盖文档右侧。是否希望另外整体移动/缩放页面（而不是正文内部插入网格列）仍需视觉验收。
- 目前拖动目标变更采用外部 CSS 位移，重点验证长文档、高刷新率、嵌套复杂组件及垂直自动滚动边缘体验；避免在大块上每帧重排或改变 ProseMirror DOM。
- 不发布至生产；保留隔离分支，待用户实际体验后再考虑合并 main。
