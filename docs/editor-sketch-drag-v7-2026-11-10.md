# V7：手绘标注跟随块拖动与工具栏状态微调

日期：2026-11-10  
实现基线：Recalloom main @ 22ddaf5

## 问题与根因

手绘 SVG 为保护 ProseMirror/contenteditable 的 DOM 完整性而绘制在文档外的 `.rk-sketch-overlay` 中。拖动 RMD 块时，原有的临时 CSSOM 规则仅位移 ProseMirror 下的真实块节点，绝对定位的 SVG 不受 CSS 位移影响；因此截图中的方框、圈选、括号在视觉上脱离文字内容。

仅在拖动时重新测量并生成 SVG 不是正确的修复。实际 Edge 测试证明，在过渡动画尚未完成的时刻重新测量会把旧像素位置与目标位移混用，反而造成新的错位和频繁绘制。

## 实施方案

- 引入纯瞬态事件 `rk-sketch-drag-preview`，块拖放状态向对应编辑器内的手绘层发布受影响节点及 Y 轴位移，不向 Markdown 写入任何元数据；
- 手绘层保持每张 SVG 的原始 DOM 所属元素。拖动时仅更新 SVG 的 `transform: translate3d` 与源元素淡出状态，过渡节奏与块移动相同；
- **拖动期间暂停标注层重绘**：ResizeObserver/MutationObserver 可能触发的重绘不再捕捉 CSS 过渡动画的中间帧；
- 放下、取消或删除临时样式时，清除会话位移并重新测量，让 SVG 在最终位置与可编辑文本准确对齐；撤销/重做沿用现有观察器更新机制；
- 静止状态、预览模式以及未参与拖动的标注行为不改变。

## 工具栏补充调整

- 移动端加号及关联块操作**取消 sticky**，与格式操作一起自然横向滚动；
- 标题下拉只包含一级至六级标题，不再将“正文”视为某种标题。再次点击当前标题级别仍调用 `toggleHeading({level})` 恢复正文；
- 对齐方式保留菜单项的已选状态提示，但**工具栏主按钮永远不显示选中高亮**，避免默认左对齐常亮；
- 保留 V6 所确定的桌面与触控端相同格式工具顺序。

## 验收

- `pnpm check` 继续审计 RMD 42 个命令入口和标题状态切换行为；
- 新增 `scripts/editor-sketch-drag-sync-v7-e2e.mjs`，在真实 Edge 以多种手绘 SVG 测试拖动中的位移、放下、撤销与拖动源透明度；
- 同步调整 V5/V6 浏览器断言：标题菜单不得存在“正文”、对齐按钮不高亮、移动端“+”能够随横向滚动离开可视区域；
