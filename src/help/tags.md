# 标签与智能推荐

标签是知识库的全局定义，具有名称、描述、颜色和别名，并分为两类：

- **智能标签（默认）**：可由用户手动指定，也可通过语义关联自动维护。
- **固定标签**：完全由用户或 Agent 手动指定，不参与自动候选或传播（例如“重要”“VIP”）。

每篇文稿与标签的关联有独立来源：**manual** 优先且不会被系统覆盖；**auto** 由 Clef-flash 模型判断。移除自动标签会记录忽略决定，避免再次添加；可以在文稿详情中恢复。

智能标签不是后台定时任务。手动增删标签时，请求会同步判断该标签是否适合相似文稿；修改正文或标题时，向量索引在生成 Embedding 后直接查询相似文章，分别使用 Clef-flash 9B 执行“文章找标签”与“变化标签找文章”。向量入库与分类并行完成，全部成功后索引才标记完成。模型失败由索引任务重试。

**不会提供独立的标签重新分析、全库扫描或定时重算入口。**

智能标签候选来自当前及历史相似文章，使用 Clef-flash 9B 的 noul 独立给出 0–1 相关性分数，当前判断阈值为 0.70（根据既有中文测试样本初步校准，并非用户必须维护标签描述）。自动产生的关联不会递归触发新的推荐。

手动添加标签、修改标签定义、合并标签和查询标签均可通过 Web 或 MCP 完成。

## Agent 的 MCP 管理工具

- `list_tags` 按名称、别名、使用情况和顺序分页查询标签。
- `get_tag` 读取定义、智能或固定类型、颜色、描述、别名、使用数量与元信息版本。
- `manage_tag` 创建、更新、合并或删除标签。更新支持类型、名称、描述、颜色和别名，重命名保留原名称作为别名。合并、删除先预览，再携带预览版本执行。
- `query_tag_records` 按标签组合查询文稿，支持全部匹配或任一匹配。
- `tag_record` 为文稿添加或移除标签。添加已有自动标签会转为手动标签，移除会保存该文稿的忽略决定。
- `get_tag_suggestions` 读取文稿的忽略标签、参考文稿与索引就绪状态。自动标签的置信度与来源可通过 `read_record` 的 `tagDetails` 读取。
- `manage_tag_suggestions` 支持 `accept_all` 批量转为手动标签，以及 `restore` 恢复被忽略的标签。

已有对象的修改携带对应的 `expectedMetadataRevision` 进行并发校验。MCP 写操作需要 `notes:write` 权限。
