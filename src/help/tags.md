# 标签与别名

标签是记录的元信息，可用于组织文档和任务列表。在侧边栏打开“标签”，按名称、别名、使用情况和使用次数查找标签。进入标签后可组合多个标签，选择全部匹配或任一匹配，并筛选有效内容、归档内容及内容类型。

## 添加标签

在文档或任务列表的信息面板中选择“添加标签”，输入名称即可查看已有标签和相似名称。选择已有标签可直接关联，也可以将输入作为已有标签的别名。需要独立分类时选择创建新标签。每条记录最多添加 32 个标签。旧数据超过此数量时会保留，可继续移除标签。

名称保留显示大小写。系统按 Unicode NFKC、首尾空白移除、连续空白合并和小写进行比较。规范化后相同的名称和别名会指向同一个标签。近似名称会提供候选项，用户决定是否复用。

## 管理标签

“标签管理”支持修改名称、描述、颜色与别名。重命名会保留原名称作为别名。标签的 ID 保持稳定。

合并和删除前先查看影响范围，包含有效内容、归档内容和重叠关联数。合并会迁移关联并去重，旧 ID 会继续指向合并目标。删除会移除关联。标签修改通过独立的元信息版本进行并发校验，正文历史版本保持独立。

## 智能标签

文稿当前版本完成索引后，后台会从已有标签目录中推荐最多 5 个标签。手动标签优先显示，智能标签带有标识、推荐理由、正文依据和依据版本。标签保存在元信息中。手动与自动标签合计仍受每条记录 32 个标签的上限约束。

在信息面板中，可以逐个或全部将智能标签转为手动标签。移除标签会保存忽略决定，之后的推荐会跳过它。在“已忽略的标签”中恢复后可重新推荐。手动添加同名标签也会清除忽略决定。

正文、标题、描述或手动标签变化后，系统会分析当前文稿，再更新最多 10 篇语义相关文稿，并重新检查上次参考的文稿。相似文稿的手动标签作为参考，每个推荐仍需得到当前正文的支持。自动推荐的变动只影响当前文稿。任务使用后台队列执行，失败自动退避重试，现有标签会保留。

“标签管理”中可以开关智能标签、调整 Workers AI 生成模型、手动分析全部有效文稿。默认模型为 `@cf/google/gemma-4-26b-a4b-it`。每个标签还可设置是否参与智能推荐、是否作为相似文章的推荐依据。生成使用已有 Workers AI 绑定，产生相应的推理用量。关闭智能标签后，已有标签继续保留。

## MCP 工具

- list_tags 支持名称或别名查询、使用情况、排序及分页。
- get_tag 返回标签定义、别名、使用数量与 metadataRevision。
- manage_tag 支持 create、update、merge、delete。合并和删除默认返回预览，执行时使用预览的 catalogVersion、标签版本和目标版本。
- query_tag_records 按稳定标签 ID 查询内容，match 支持 all/any。
- tag_record 以 tagId 或名称添加或移除关联，并传入记录的 expectedMetadataRevision。

- get_tag_suggestions 返回全局设置或指定文稿的任务状态、忽略标签与参考文稿。
- manage_tag_suggestions 支持重新分析、全部采纳、恢复忽略及全局配置。

标签关联修改会更新记录的元信息版本。标签定义修改使用标签自身的版本。相似度建议在客户端计算。
