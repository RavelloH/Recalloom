# 快照导出、校验与恢复

Recalloom 使用 recalloom-snapshot-v5 格式，分页保存文档、元数据、版本历史、标签定义与关联（稳定 ID、别名、颜色、描述和推荐开关）、标签的手动或自动来源、推荐依据与忽略决定、人工关系、任务全局顺序、Wiki 路径到 UUID 的持久绑定，以及**智能集合的名称、描述、完整规则、稳定 ID、修订号和时间戳**。集合定义只包含在第一页（包括没有文档的知识库），其余页面的 collections 为 []；集合的实时查询结果不会被复制进快照。旧 v2/v3/v4 快照仍可导入，旧格式没有保存的能力无法追溯恢复。导入后按整批记录重建 Wiki 引用投影。快照可能包含敏感的历史正文，应按敏感数据妥善存放。

## 导出

1. 调用 export_snapshot，不传 cursor；可设置 limit 控制每页返回的记录数（最多 5）。
2. 读取返回的 page.nextCursor，依次获取后续页面，直到为空。
3. 保持原始顺序与内容，收集所有页面为 {pages:[...all pages...]}。
4. 记录并核对变更水位、任务 orderVersion、标签目录版本、智能集合 collectionHash 及逐页 SHA-256。智能集合的新增、编辑或删除即使不产生文档变更事件，也会使后续页面导出失败；必须重新开始，不能拼接不同状态的页面。

## 验证和导入

import_snapshot 接收**完整** bundle={pages:[...]}，而不是其中某一页。默认 dryRun=true，只进行格式、哈希、冲突及规模校验，不修改当前数据。

只有在用户明确授权真实导入、并已充分检查覆盖/冲突风险后，才将 dryRun=false；服务端以原子事务导入，并保护已有 UUID 和路径。限制包括最多 300 条记录、300 个智能集合、2,000 个文件夹、3,000 条人工关系、100 页、700 条事务语句，完整 bundle JSON 不超过 6,000,000 个 UTF-16 代码单元。现有集合 UUID、记录 UUID 或路径冲突会被拒绝，不会覆盖原库；集合名称可以重复。智能集合的规则会校验结构，引用的文件夹/任务列表保持稳定 ID；如果导入的标签按名称合并到目标库已有标签，集合规则中的标签 ID 会相应映射。原本已失效的引用不会凭名称错误地重新绑定。空库恢复时，v3 及后续格式保留任务的全局位置；向已有任务的库合并时，按导入任务的原有相对顺序追加到末尾。验证期间目标库发生变化可能导致拒绝整批导入，需要重新开始。切勿假设可以无条件覆盖整个知识库。

## 与常规版本恢复的区别

- 恢复单条记录的旧版本：使用 restore_record，并提供 expectedRevision。
- 检查历史正文差异：使用 version_history、read_record(revision)、diff_revisions。
- 跨实例/整库快照迁移：使用 export_snapshot/import_snapshot。

快照导入并不是一项自动后台任务，也不是编辑 Markdown 的替代操作。涉及风险的真实写入应先 dryRun 和人工确认。
